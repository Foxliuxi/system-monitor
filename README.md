# 系统实时监测 · System Monitor

**简体中文** ｜ [English](README.en.md)

一个跑在本机的实时监测工具。**系统资源（CPU / 内存 / 显卡 / 硬盘 / 温度 / 进程排行）
+ 网络质量 + 硬件对网络的真实影响分析**，浏览器里看实时曲线，
不装服务、不上传数据、不依赖外网。

界面中英双语（右上角切换），分析结论也跟随语言——不是只翻了个菜单。
支持 NVIDIA / AMD / Intel 三家显卡，温度来自 LibreHardwareMonitor（可选组件）。

## 界面怎么看

**布局是一屏式的，不需要滚动就能看全所有数据。** 分两大区，**系统资源在上、网络状态在下**：

```
顶栏：标题 · 健康评分环 · 实时状态
KPI 七联：CPU · 显卡 · 内存 · 磁盘I/O │ 下行 · 延迟 · 丢包

──── 系统资源  SYSTEM ────────────────────
CPU ─────────┬──────── 显卡
内存 ─────────┼──────── 硬盘
温度（CPU / 显卡 / 硬盘 三格横排）
进程监控（CPU Top10 │ 内存 Top10）

──── 网络状态  NETWORK ───────────────────
实时吞吐 ─────┼──────── 延迟趋势
链路（横向 chips）

▶ 提醒条（默认收起，只显示一行结论）
```

| 区域 | 内容 |
|------|------|
| 顶栏 | 机器型号与系统、**健康评分环**、**配色切换（暗 / 亮）**、实时连接状态 |
| KPI 七联 | 系统四项（CPU/显卡/内存/磁盘）在前，网络三项（下行/延迟/丢包）在后 |
| CPU | 占用率、每核占用柱状、频率、负载状态 |
| 显卡 | 利用率、核心温度、显存、功耗、风扇、频率（NVIDIA） |
| 内存 | 占用率、已用/可用、**当前占用最高的应用** |
| 硬盘 | 各分区容量条、实时读写速率、物理盘健康 |
| 温度 | CPU / 显卡 / 主板 / 硬盘，读不到的项写明原因与来源 |
| 进程监控 | CPU / 内存各 Top 10 并排，**同名进程已合并**，带相对占比条 |
| 实时吞吐 | 下行（蓝）上行（紫）双曲线，可切 1/5/15 分钟 |
| 延迟趋势 | 到网关（绿）、到公网（黄），**红点=该次丢包** |
| 链路 | 横向 chips：网卡、类型、速率、WiFi 信号/频段/信道、上行、抖动、连接数、网关 |
| 提醒（折叠） | 默认收起成一行结论，点开看完整因果链与操作建议 |

**为什么提醒默认收起**：它是最长的内容（6-10 条、每条 3 段文字），展开会挤掉监控数据。
收起状态那行就是结论本身，不展开也知道该做什么。

**为什么内存卡显示"占用最高的应用"**：内存卡本身内容少，被拉到与硬盘卡等高时会空一块。
与其留白，不如显示一条真正有用的信息。

## 指标正常值参考

判断"好不好"需要基准线，这些是经验区间（不是标准，环境差异很大）：

| 指标 | 优秀 | 可接受 | 需要查 |
|------|------|--------|--------|
| 到网关延迟（有线） | < 1 ms | 1-2 ms | > 3 ms |
| 到网关延迟（WiFi） | < 3 ms | 3-6 ms | > 10 ms |
| 公网延迟（国内同城） | 5-15 ms | 15-40 ms | > 80 ms |
| 抖动（相邻采样变化） | < 5 ms | 5-20 ms | > 40 ms |
| 丢包率 | 0 % | < 0.5 % | > 1 % |
| 网卡错误包 | 0 | 偶发个位数 | 持续增长 |
| CPU 占用 | < 50 % | 50-75 % | > 85 % |

**关键判据：先看丢包发生在哪一跳。**
到网关就丢 → 问题在本机（无线干扰/网线/驱动），换运营商无用。
网关不丢、公网丢 → 问题在上游，本机硬件无辜。

### 丢包率到底怎么算的（可以自己核对）

对着 `ping www.baidu.com -t` 的数字觉得对不上时，看这四条：

| 项 | 实际做法 |
|---|---|
| 探测目标 | 默认 `223.5.5.5`（阿里 DNS）。**你 ping 的域名不一定是同一个目标**，想看同一路径就加 `--ping-target www.baidu.com` |
| 超时窗口 | **4000 ms**，与 Windows `ping` 默认一致。窗口设小了会把"慢回包"误判成"丢包" |
| 分母 | **真正发出去的探测次数**，不是页面采样帧数，也不含首帧未探测 |
| 发包失败 | 解析不到主机 / 无路由 / ICMP 被拦 → 记为 `error`，**不计入丢包率**，单独显示 |

界面丢包那一格的副标题就是账本：`超时 2/57 次` 读作"57 次探测里 2 次超时"，
鼠标悬停能看到完整口径。曲线上的红点只在**确实判定超时**时才打。

> 历史版本用 900 ms 超时窗口，实测这台机器公网 RTT ≈ 1000 ms，于是每次都被判超时、
> 报出 90% 的假丢包；同一时段用 `ping -n 10 www.baidu.com` 实测只有 10%。
> 已改为 4000 ms 并把"超时"和"发包失败"分开统计。

## 温度：数据从哪来

Windows **没有系统级的通用温度接口**，尤其 AMD 平台连 ACPI 热区都不暴露。
所以 CPU / 主板 / 硬盘温度由一个专业工具提供，本程序只做消费方：

| 温度 | 来源 | 前提条件 |
|------|------|---------|
| 显卡 GPU（NVIDIA） | `nvidia-smi` | NVIDIA + 驱动，**不需要管理员** |
| 显卡 GPU（AMD / Intel） | LibreHardwareMonitor（内部走 AMD ADL / Intel IGCL） | LHM 常驻；**核显多数没有独立温度传感器**，独显才有 |
| **CPU / 主板 / 硬盘** | **LibreHardwareMonitor 的 HTTP 接口**（`127.0.0.1:8085`） | LHM 常驻运行即可，服务开关已写进它的配置 |
| 兜底 | WMI `MSAcpi_ThermalZoneTemperature` | 需管理员；多数 AMD 主板读不到 |

显卡数据按可靠性依次降级：**nvidia-smi → LibreHardwareMonitor → 如实说明不可用**。
这样同一套界面能覆盖三家显卡，缺哪条腿都不会显示假数字。

### 分发时（v1.6 起）：温度组件随安装包走，但由使用者选择

安装包里带了一份 LHM（压成 `LibreHardwareMonitor.zip`，约 5.8 MB），安装时会问一句
「一并安装温度组件吗」。选 Y 就解压到程序目录、建开始菜单快捷方式、提权启动一次；
选 N 就完全跳过，主程序照常装。

为什么做成可选而不是默认塞进去：

1. 它要装**内核驱动**（PawnIO），属于改变系统底层的行为，不该替别人决定
2. 它要**管理员权限**，而主程序刻意做成免提权
3. 它是第三方开源软件（MPL 2.0），分发要带许可证——`LibreHardwareMonitor.zip` 里已附 `LICENSE`

分发用的那份配置是**精简版**（只有 255 字节，三个开关），不是开发机上的那份——
把本机的传感器偏好带出去，到别人的主板上全是不匹配的条目。


### 两个必须知道的坑（实测踩到的）

**1. 它的设置文件不叫 `LibreHardwareMonitor.exe.config`。**
源码里是 `Path.ChangeExtension(Application.ExecutablePath, ".config")`——把 `.exe` 整个换成
`.config`，所以真正的设置文件是 **`LibreHardwareMonitor.config`**。
我一开始改的是 `.exe.config`（那是 .NET 运行时配置），改了半天它根本不读，
还据此得出过"配置写进去就崩"的错误结论。**改配置前先确认文件对不对。**

**2. 温度项里混着阈值，不能直接取最大值。**
NVMe 盘会同时报 `Composite Temperature 45°C` 和 `Warning Temperature 89°C`——后者是
告警阈值，不是当前温度。程序按名字过滤掉 warning/critical/max/limit 这类项，硬盘取
`Composite Temperature` 优先。另外无型号名的 USB 桥接盘会报 `0.0 °C`，也已过滤。

**程序不会为了好看编一个温度数字。** 读不到就写读不到，并告诉你为什么、怎么才能读到。

## 硬件是怎么影响网络的（原理）

这是本工具分析引擎的判断依据，也是你理解结论的钥匙：

**1. 链路媒介决定上限**
WiFi 与有线的差距不在"标称速率"，而在**重传**。无线是共享介质，冲突后要退避重发，
每次重传都是一次额外延迟——这就是 WiFi 打游戏跳 ping 的根源。有线是点对点全双工，没有这个问题。
所以"千兆口空着却在用 WiFi"是本工具优先级最高的告警。

**2. 2.4GHz 是拥挤频段**
只有 1/6/11 三个互不重叠信道。蓝牙、无线键鼠、微波炉、邻居 AP 全在这段频谱上。
5GHz 干扰源少一个量级，且 802.11ac 下带宽高 3-6 倍。

**3. USB 无线网卡有物理短板**
靠 USB 总线供电、天线小；更麻烦的是 USB 3.0 接口在工作时会在 2.4GHz 附近产生宽带噪声，
USB3 硬盘/扩展坞离网卡越近，2.4G 收包错误率越高。这是可复现的实测现象。

**4. CPU 影响的是"中断响应"，不是"带宽"**
每收一个包都要触发中断、走协议栈。CPU 打满时中断被推迟，表现为吞吐抖动和延迟尖刺。
典型形态：**单核 100% 而总占用只有 30%**——网卡中断集中在单核（RSS/RPS 未生效）。

**5. 电源策略会偷偷降速**
平衡/节能模式启用 PCIe ASPM 与网卡省电，链路空闲后重新唤醒有额外延迟，
体感就是"停一会儿再动就卡一下"。高性能模式可消除。

**6. 有线链路降速 = 物理层问题**
千兆网卡协商成 100Mbps，九成是网线只有 4 芯、水晶头氧化、或墙内面板接线错误。
软件层面无解，换线直连可立即验证。

**7. 内存/磁盘对网络影响有限**
除非内存耗尽压缩 socket 缓冲区，否则 48GB 内存和 SSD 基本不会成为网络瓶颈。
本工具不会为了凑数给你报"磁盘建议优化"。

见 **`deliverables/打包与分发说明.md`**。一句话版本：

发 `deliverables/系统实时监测_v1.6_便携版.zip`（13.8 MB，含温度组件），对方解压双击就能跑。

## 已知限制（写清楚，不藏）

- **位置提醒**：程序目前在 WorkBuddy 的工作区目录下。如果以后清理或迁移工作区，这个文件夹会跟着走。
  想长期留着，把整个 `netmon` 文件夹复制到 `C:\Tools\netmon` 之类的位置，
  再把桌面启动器里的路径改过去即可（就改那一行）。
- **仅 Windows**：WiFi 信号/信道、网卡清单、电源计划依赖 `netsh`/PowerShell/注册表。
  采集核心（psutil 部分）跨平台，但分析引擎的硬件推断是 Windows 专用。
- **只监测本机**，不是局域网监控。
- **显卡监控覆盖 NVIDIA / AMD / Intel，但依赖不同**：NVIDIA 走 `nvidia-smi`（最准）；
  AMD 走 LHM 的 ADL、Intel 走 IGCL，都要 LHM 在跑。**Intel / AMD 的核显多数没有独立
  温度传感器**（与 CPU 同一块晶片），只有独显才有温度。缺数据时明确显示「不可用」并说明原因，
  绝不给假数据。
- **CPU / 主板 / 硬盘温度依赖 LibreHardwareMonitor 常驻运行**（已装到 `C:\Tools\LibreHardwareMonitor`）。
  它没运行时，程序自动回退到 ACPI 热区；还读不到就如实标「不可用」并说明原因，绝不编数字。
- **进程排行按应用名聚合**：Chrome/Edge 这类多进程应用会合并成一行（显示 ×N 进程数），
  这样才看得出"谁在吃资源"，而不是被同一个浏览器的 20 个渲染进程刷屏。
- **系统空闲进程不计入排行**：`System Idle Process` 统计的是空闲时间，
  混进来会以 90% 占满榜首，把真实应用全挤下去。
- **仅监听 127.0.0.1**：不对外开放，局域网其他机器访问不到（这是有意的）。
- **英文模式下仍会有中文出现的位置**：网卡型号/名称（Windows 中文系统的设备名）、
  电源计划名、部分 LHM 传感器名——这些是**操作系统返回的数据**，不是界面文案。
  硬翻会把「以太网」变成「Ethernet」，反而让人对不上设备管理器里的名字。
- **不记录历史到磁盘**：内存里保留 30 分钟，重启即清空。要长期趋势需自行接时序库。
- 延迟探测依赖 ICMP，部分网络禁 ping 会显示 `--`，此时看 DNS/TCP 两项。
