# 系统实时监测 v1.6 · 打包与分发说明

> 面向：要把这个工具发给别人用的人（也就是你）
> 日期：2026-11-17 ｜ 构建环境：Python 3.13.14 / PyInstaller 6.22.3 / IExpress（Windows 自带）
> 本版新增：**温度组件随安装包分发，安装时由使用者选择装不装**；**显卡支持 AMD / Intel**

## 一、产物清单

全部在 `deliverables/` 下，任选其一发：

| 文件 | 大小 | 适合谁 | 说明 |
|------|------|--------|------|
| **系统实时监测_v1.6_便携版.zip** | 13.8 MB | **推荐首选** | 解压即用，exe + 使用说明 + 温度组件目录。不写注册表、不留残留 |
| **系统实时监测_v1.6_便携版.exe** | 8.1 MB | 只想要主程序 | 单文件本体，双击即跑。**不含**温度组件 |
| **系统实时监测_安装包_v1.6.exe** | 14.0 MB | 想要"装好就有快捷方式"的人 | 双击安装，**会问要不要装温度组件**，带桌面/开始菜单快捷方式与标准卸载入口 |

`SHA256SUMS.txt` 是校验值——传输完让对方核一下，能确认文件没被改动或截断。

**推荐发 zip 而不是裸 exe**：微信/QQ/邮件对 `.exe` 附件拦截率很高，`.zip` 基本能过。

### 两个版本的差别

| | 便携版 zip | 安装包 |
|---|---|---|
| 使用 | 解压 → 双击 exe | 双击 → 装完自动启动 |
| 位置 | 你放哪就在哪 | `%LOCALAPPDATA%\Programs\系统实时监测` |
| 快捷方式 | 无，自己拖 | 桌面 + 开始菜单 |
| 温度组件 | 包里有 `LibreHardwareMonitor\` 目录，想用就双击里面的 exe | 安装时问一句，选 Y 才装 |
| 卸载 | 删掉整个文件夹即可 | 设置 → 应用 → 卸载 |
| 需要管理员 | 不需要（温度组件单独要） | 不需要（温度组件单独要） |

两个版本的功能完全一样，只是安装方式不同。

## 二、怎么发给别人（照做即可）

1. 把 `系统实时监测_v1.6_便携版.zip` 发给对方
2. 附上这段话（省得对方反复问你）：

> 解压后双击「系统实时监测.exe」。会弹一个黑窗口，那是程序本体不是报错，
> 浏览器会自动打开看板。如果 Windows 提示"已保护你的电脑"，点「更多信息」→「仍要运行」。
> 关掉黑窗口监控就停了。
>
> 想看 CPU / 主板 / 硬盘温度，把解压后那个 LibreHardwareMonitor 文件夹里的
> LibreHardwareMonitor.exe 双击运行一次，UAC 点「是」。它是第三方开源软件，
> 每次启动都要点一次 UAC（要装内核驱动才能读温度）。不装也能用，温度栏会写明原因。

3. 如果发的是安装包，第 2 条里那段"想看温度"的话可以省掉——
   安装时它会自己问一句「一并安装温度组件吗」。

## 三、对方一定会遇到的提示（提前知道就不慌）

**1. SmartScreen：「Windows 已保护你的电脑」**

原因只有一个：**这个 exe 没有数字签名**。代码签名证书一年几千块，个人工具不划算。
提示里点「更多信息」→「仍要运行」即可，不影响使用。

**2. 杀毒软件报警（火绒/360/Defender）**

PyInstaller 打的 exe 是"自解压 + 释放临时文件 + 起本地 HTTP 服务"，这几个行为
在启发式引擎眼里和木马高度重合，**误报率天然偏高**。

我把结构从"目录型（200 多个文件）"改成"单文件"就是为了减少这类误报。
若仍被拦：

- 让对方把 exe 加入白名单（火绒：安全设置 → 信任区）
- 或者换用另一个打包参数重打（见第六节）

**这一条我在你的机器上没法替对方验证**，因为对方的安全软件组合我接触不到。

**3. 安装温度组件时弹 UAC**

这是它要加载内核驱动（PawnIO）才能读温度，**躲不掉**。点「是」即可。
之后每次从快捷方式启动它，都会再问一次——这也是正常的，不是出错。

**4. 端口占用**

程序默认监听 `127.0.0.1:8770`。被占用时会自动顺延到 8771、8772，
实际地址会打印在黑窗口里。**只监听本机**，局域网其他机器打不开这个页面，这是有意的。

温度组件用 `127.0.0.1:8085`，同理只对本机开放。

## 四、温度组件到底装了什么、为什么要它点头

安装包里的 `LibreHardwareMonitor.zip`（5.8 MB，40 个文件）是 **LibreHardwareMonitor v0.9.6**
的运行目录。选 Y 时发生四件事：

1. 解压到 `%LOCALAPPDATA%\Programs\系统实时监测\LibreHardwareMonitor`
2. 给它建一个开始菜单快捷方式（「温度组件 LibreHardwareMonitor」）
3. 提权启动一次——**首次必须提权**，它要装内核驱动
4. 安装脚本等最多 10 秒，探测 `127.0.0.1:8085` 是否就绪，把结果打印出来

### 为什么做成可选，而不是默认装

| 理由 | 说明 |
|---|---|
| 装内核驱动 | 属于改变系统底层的行为，不该替别人决定 |
| 需要管理员 | 主程序刻意做成免提权，不该被一个可选功能拖下水 |
| 第三方许可 | MPL 2.0，分发要带许可证（zip 里已附 `LICENSE`） |
| 体积 | 5.8 MB，不想要温度的人没必要下 |

不装不影响任何其他功能：温度三格显示「不可用」并写明原因，网络、CPU、内存、硬盘、
进程排行、NVIDIA 显卡全都正常。

### 分发的那份配置是精简过的

LHM 默认**不开** Web Server，而本程序正是通过 `http://127.0.0.1:8085/data.json` 读它。
不预置配置的话，用户装完还得自己去菜单里勾选，等于白装。

所以 `make_lhm_pack.py` 生成一份 **255 字节**的配置，只含三个开关：

```xml
<add key="runWebServerMenuItem" value="true" />   <!-- 启动即开 Web 服务 -->
<add key="minCloseMenuItem" value="true" />       <!-- 关窗口只最小化，不退出 -->
<add key="minTrayMenuItem" value="true" />        <!-- 最小化到托盘 -->
```

**不能直接分发开发机上的那份 `LibreHardwareMonitor.config`**：它 691 KB，里面全是
本机硬件标识符（`/lpc/nct6798d/0/control/3/plot` 这种）。到别人的主板上一条都对不上，
轻则一堆无效项，重则界面里部分传感器默认关闭。

### 卸载时会发生什么

- 温度组件目录随主程序目录一起删除（`rd /s /q`）
- 卸载脚本会先按**路径前缀**结束 `LibreHardwareMonitor.exe`，不误杀用户自己另外装的那份
- **内核驱动 PawnIO 不会随之移除**——这是 LHM 的既定行为，不是残留 bug。
  它留在系统里无害、不占资源，也没必要为它去设备管理器折腾

## 五、构建：怎么重新打一次

改完代码要重新打包时，双击项目根目录的 **`build_all.bat`** 即可。它做五件事：

```
[1/5] 建 venv（首次）并装 psutil + pyinstaller（走阿里云镜像，约 35MB）
[2/5] 生成图标（build/make_icon.py，纯标准库画 ICO，不依赖 Pillow）
[3/5] PyInstaller 打成单文件 exe      → dist-onefile/系统实时监测.exe
[4/5] 组装 staging：
        · 主程序 exe
        · install.cmd / uninstall.cmd（UTF-8 转 GBK）
        · LibreHardwareMonitor.zip（来自本机 LHM 目录）
      再用 IExpress 打成安装包
[5/5] 组装便携版 zip → deliverables/系统实时监测_v1.6_便携版.zip
```

耗时约 1-3 分钟。

**前置条件（第 4 步需要）**：本机得有一个 LibreHardwareMonitor 目录作为源，
默认读 `C:\Tools\LibreHardwareMonitor`；不在这个位置就用环境变量覆盖：

```
set LHM_SRC=D:\somewhere\LibreHardwareMonitor
build_all.bat
```

找不到时 `make_lhm_pack.py` 会直接报错退出，**不会**悄悄产出一个没有温度组件的包。

### 为什么用 IExpress 而不是 Inno Setup

试过三条路，最后选 IExpress：

| 方案 | 结果 |
|------|------|
| Inno Setup | 体验最好，但要额外装一个开发工具（还要管理员权限装），为一个人工具引入新依赖不划算 |
| 7-Zip SFX（`7z.sfx` / `7zCon.sfx`） | **默认解压到"当前目录"**——双击后会在安装包旁边散落 20MB 文件，重装还弹"是否覆盖"。可配 `Directory` 但仍是固定路径，重装必撞 |
| **IExpress（Windows 自带）** | 解压到 `%TEMP%\IXPxxx.TMP`、执行指定脚本、用完自清。零外部依赖，行为正确 |

**IExpress 的硬限制（踩过）**：它处理不了子目录。带 `系统实时监测\` 这种目录结构时，
CAB 里会**静默丢弃**整个目录，只解出脚本——安装脚本随即报"找不到主程序"。

这就是为什么载荷是**四个平级文件**：主程序单文件 exe + 两个脚本 + 一个 LHM 的 zip。
温度组件那几十个文件（还有 11 个语言子目录）必须先压成 zip，安装时用
`[IO.Compression.ZipFile]::ExtractToDirectory` 展开。

不用 `Expand-Archive` 是因为它逐个文件解，慢一截；ZipFile 一次性解完。

## 六、减少误报的备选参数

如果对方被拦得很厉害，可以把 `build/build_pack.py` 里的 `--onefile` 换成 `--onedir`
（打包成目录），或者追加：

- `--noupx`：PyInstaller 现在默认就不 UPX，若手工加过 UPX 压缩要去掉（UPX 是高误报源）
- 给 exe 补一个版本信息（当前已通过 `build/version.txt` 写入，别删）
- 有条件的话买代码签名证书，一次性解决 SmartScreen + 多数误报

这些都属于"有条件再做"，不做也能用。

## 八、已知限制

- **仅 Windows 10/11 64 位**。WiFi 信道、网卡清单、电源计划依赖 `netsh`/PowerShell/注册表；
  LHM 需要 .NET Framework 4.7.2（Win10 1809 之后系统自带 4.8，不需要另装）
- **首次启动慢 1-2 秒**：单文件 exe 要先解包到 `%TEMP%\_MEIxxxx`，这是单文件的固有代价
- **安装包二次安装可能失败**：若上次安装被强杀，`%TEMP%\IXP*.TMP` 残留会导致这次失败。
  删掉该目录重试即可（这是 IExpress 的行为，脚本层无法兜住）
- **温度组件每次启动都要 UAC**：内核驱动加载躲不掉。想彻底免点，用托盘右键 →
  `Options` → 勾 `Run on Windows startup`，它会注册一个最高权限的登录任务
- **AMD / Intel 显卡支持取决于 LHM 的驱动层**：Radeon 独显（GCN/RDNA 系）和 Arc 独显
  基本都能读温度；**AMD / Intel 的核显多数没有独立温度传感器**（与 CPU 同 die），
  这类机器上显卡温度显示"不可用"是正确的，不是 bug
- **不写盘、不留历史**：数据只在内存，关掉就没了。要看长期趋势得另做落盘

## 十、一句话总结

**要发给别人，发 `deliverables/系统实时监测_v1.6_便携版.zip` 就够了。**
对方解压双击就能用；遇到 SmartScreen 点"仍要运行"；想要温度就运行包里那个
LibreHardwareMonitor.exe。安装包是给"想要正规安装体验"的场景准备的，多一步勾选，
功能上没有区别。
